One model, many views.

Give each element a stable ID and reuse it wherever it matters. A context diagram can show who uses the system, while a focused view shows how the service reaches its data.

Model the relationships

Use model to declare the things in your architecture and the connections between them.

service tracking "Tracking API"
database shipments "Shipment store"
relation reads tracking -> shipments "Reads"

Choose what a view shows

Use include to focus a view. Start with automatic layout and position elements where it helps tell the story.

view data "Data access" {
  include tracking, shipments
  place shipments bottom of tracking
}

Documentation

Embed a diagram

Put the browser bundle next to your HTML and pass a complete architecture document to arch.render(). The result is inline SVG.

<div id="diagram"></div>
<script src="arch.min.js"></script>
<script>
  arch.render('#diagram', `architecture "Example" {
    model {
      service api "API"
      database data "Store"
      relation reads api -> data "Reads" { type access }
    }
    view overview "Overview" {}
  }`);
</script>

Common tasks

Choose a diagram type

Use diagram tree for a hierarchy, diagram sequence for ordered messages, or diagram timeline for dated events. Connected views are the default.

Validate against a profile

A profile defines allowed element types, relationship endpoints, and viewpoint rules. Studio loads the included NAFv4.1, ADMBw, and ArchiMate profiles. Select a registered profile with config { profile PROFILE }.

Share source or a dashboard

Keep the editable .arch or JSON source with your project. Export SVG for a single view or use Studio to download a standalone HTML dashboard that includes the diagrams and their source.
